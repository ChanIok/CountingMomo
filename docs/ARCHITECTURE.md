# 按功能查找状态与流程

从 `main.cpp` 进入程序：初始化 UI 线程 COM 套间，创建 `core::AppState`，由应用初始化模块先处理单实例与提权，再初始化业务窗口并运行 Win32 消息循环。

## 一个状态根，按功能持有

`core/state/app_state.hpp` 只前向声明模块状态，并以 `unique_ptr` 持有它们。
需要读写字段的实现文件显式包含对应的 `state.hpp`。
`app_state.cpp` 只分配子状态，并在默认析构中自然释放成员；它不启动服务、停止线程或销毁窗口。

| 状态 | 内容 |
| --- | --- |
| `state.startup` | 当前登录会话的单实例互斥量句柄 |
| `state.scan` | 任务阶段、UI 进度快照、线程交接、本次请求、扫描资源、批次和当前分类状态 |
| `state.capture` | D3D／WGC 会话、单张 GPU 参考纹理、比较资源、读回纹理、帧通知与稳定计时 |
| `state.navigation` | 分类目录、导航阶段、最近帧 |
| `state.result` | 上次完整成功结果，包含分类数组、统计和完成警告 |
| `state.settings` | 持久化设置及配置文件路径 |
| `state.window` | 游戏窗口句柄及窗口恢复信息 |
| `state.main_window` | 主窗口、视图、通知、复制反馈和关闭意图 |
| `state.status_window` | 悬浮窗口及其显示、绘制状态 |

主题、共享渲染资源和 i18n 状态同样由 `AppState` 持有。

批次、当前分类与导航会话不在调用栈中另建上下文。流程函数接收 `AppState&`，
从所属模块状态取得运行环境；参数只表达本次操作的输入。图像匹配等纯计算仍接收图像、布局等明确输入，计算临时值保留局部。

## 应用生命周期显式编排

- `core/initializer/initializer.hpp/.cpp`：先设置系统语言并处理单实例与提权；只有最终管理员实例才加载设置、探测游戏窗口、初始化主题和共享图形资源、创建主窗口、订阅主题变化并创建状态浮窗。返回 `startup::Action::run` 才进入消息循环，返回 `exit` 则结束本次启动。任一步失败即返回，已有资源交给统一 shutdown 收尾。
- `core/shutdown/shutdown.hpp/.cpp`：关闭 UI 操作入口、停止并等待扫描任务、撤销主题监听、销毁状态浮窗和主窗口，最后释放单实例句柄。实际操作由对应模块的自由函数完成，不在 shutdown 中展开资源实现。
- `main.cpp`：保证正常退出、启动交接、用户取消提权、初始化失败、消息循环失败和异常路径都经过 shutdown。之后才析构 AppState，最后撤销 UI 线程 COM 套间。

各模块的关闭入口依据实际资源处理部分初始化状态，不另设初始化步骤注册表。
`unique_ptr`、`ComPtr` 等仍通过自然析构释放持有的对象；显式 shutdown 负责需要顺序的停止、等待、退订和窗口关闭。
单次扫描的 WGC 会话、任务线程 COM 套间和游戏窗口恢复仍由扫描模块配对管理，不推迟到应用退出。

## 先检查已有实例，再请求管理员权限

`core/startup/startup.hpp/.cpp` 使用 `Local\CountingMomo.SingleInstance` 命名互斥量限制同一 Windows 登录会话内的实例数，不按 exe 所在目录区分。
互斥量只用作存活标记，不取得线程所有权；创建或访问失败返回错误，已有实例则由 initializer 通知其主窗口并结束本次启动。

manifest 保持 `asInvoker`，让程序能在 UAC 之前判断是否已有实例。只有没有实例且当前未提权时，才释放单实例句柄并通过 `runas` 启动实际 exe 路径；转交原有命令行与窗口显示参数，不依赖当前工作目录或固定文件名。
管理员子进程重新争用同一互斥量，再进入业务初始化。用户取消授权直接退出；其他提权失败返回错误，不以普通权限继续运行，也不读取或写入 `data/`。

主窗口只为无参数的 `activate_instance` 消息开放跨权限投递。后续启动进程向已有实例授予前台激活权限并投递消息；主窗口收到后直接调用 `show()` 恢复并置前，不按扫描阶段分支。
已有实例尚未创建窗口或已经销毁窗口时，本次启动直接退出，不等待或创建第二个业务实例。

## 从用户动作进入功能 usecase

- `features/scan/usecase.hpp/.cpp`：启动、停止、接收进度与终态，以及任务线程中的全分类扫描编排、窗口恢复和资源释放。
- `features/scan/job.hpp/.cpp`：单个任务线程的启动、同步交接、COM 初始化和回收。
- `features/scan/scan.hpp/.cpp`：单分类分页采集；页面、累计数组和最近图片存放在 `state.scan->category`。
- `features/scan/control.hpp/.cpp`：停止标志及工作线程的 F8 检测。窗口操作调用这里响应取消，不拥有扫描取消入口。
- `features/capture/capture.hpp/.cpp`：在扫描线程中启动捕获、等待帧通知、执行 GPU 判稳、稳定后读回完整图片和关闭会话。状态直接归 `AppState::capture`，无共享会话包装和自定义析构。
- `features/capture/comparison.hpp/.cpp`：编译比较着色器、创建 GPU 资源、比较当前 WGC 纹理并按需更新唯一参考纹理、等待已提交命令完成。
- `features/navigation/navigation.hpp/.cpp`：导航能力，通过 `AppState&` 访问会话状态；不持有指向扫描上下文的借用指针。
- `features/result/usecase.hpp/.cpp`：复制与保存完整成功结果；JSON 序列化与原子写入由 `result.hpp/.cpp` 提供。
- `features/settings/usecase.hpp/.cpp`：加载、保存及应用设置变更。窗口标题和绘制更新留在 UI 边界。

UI 将按钮、F8 和自定义扫描消息交给对应功能入口。主窗口负责关闭意图和通知到期，不再通过 `app` 总管转发业务操作。

## 资源随版本发布，数据随程序目录携带

`utils::file::executable_directory()` 返回 exe 所在目录，获取失败或路径截断时返回错误，不退化为当前工作目录。
只读 PNG 素材从该目录的 `resources/` 加载，更新时与 exe 一起替换。

`utils::file::data_directory()` 取得并创建 exe 同级的 `data/`，已存在的目录可直接复用。
设置使用 `data/settings.json`，异常诊断按需写入 `data/diagnostics/<时间戳>/`，不通过设置文件路径推导诊断位置。
数据目录不使用 AppData，不提供模式检测、自动迁移或写入失败后的其他目录回退。
发行包不包含本机 `data/`；搬迁或更新时由用户携带或保留该目录。

创建目录失败返回包含路径的结构化错误；设置保存失败沿用简短通知，当前进程中的设置继续生效。
正式成功结果仍保存在内存中，只在用户主动另存时写入所选位置。

## 线程所有权决定访问方式

- **UI 线程**读写扫描任务阶段、已消费进度、上次成功结果、设置、通知及窗口显示状态。
- **扫描线程**同步执行扫描，独占批次、当前分类、导航会话及捕获资源。本次请求启动前写入，线程回收前保持不变。
- **WGC 回调线程**仅在 `FrameArrived` 时发送通知，不取帧、不操作 D3D、不执行导航或扫描。扫描线程被唤醒后才消费帧池并执行 GPU 比较，只有稳定候选才转换成 CPU 图片。

工作线程在锁内发布 `latest` 进度和 `pending` 终态，通过只投递 UI 消息的回调唤醒主线程。
UI 在锁内取出快照；取得终态后先回收线程，再发布结果。终态单独交付，不被合并的进度覆盖。
集中持有状态不改变这些同步边界，UI 不读取正在采集的数组和工作资源。

## 固定定义归所属功能模块

不加载外部布局或分类配置，固定定义不进入 `AppState` 的可变运行状态。

- `features/scan/layout.hpp/.cpp`：以只读 `Layout` 提供客户区尺寸、GPU 比较域、三列网格、阅读边界与滚动区。单屏与带滚动条页面选择不同列数组，不修改布局。
- `features/scan/vision.cpp`：卡片与问号采样区、星星固定前景点和亮度标定、滚动条采样带、识别与锚点匹配阈值。
- `features/navigation/navigation.cpp`：唯一的分组与分类有序表、导航布局、匹配阈值和输入等待。图标文件名为 `<id>.png`；运行目录只持有指向静态定义的指针和加载后的图像资源。
- `features/scan/scan.cpp`：重叠行数、翻页上限、首次滚动标定格数。每格位移除以本次实际发送的格数。
- `features/scan/usecase.cpp`：统一的帧超时与稳定时长；用例将超时传给导航和页面采集，将稳定时长传给捕获。
- `features/window/window.hpp`：游戏进程名及单次滚轮输入上限，初始化、扫描和导航共同引用。

`Request` 只包含本次目标窗口与诊断根目录。PNG 素材仍从程序旁的 `resources/` 加载；素材缺失、尺寸不符及画面捕获失败仍按运行时错误处理。
布局几何、采样点边界、分类 ID 唯一性及动态分类翻译键通过编译期检查约束。主题与语言选项仍由 settings 持久化；扫描结束时游戏窗口无条件恢复。

## GPU 统一判稳，稳定后才读回

主线为：发送输入 → 记录操作完成源时间 → 等待通知并取原始帧 → GPU 精确比较 → 持续相同达到稳定时长 → 读回完整客户区 → 执行业务分析。分类导航、分类栏滚动和物品翻页共用这一入口。

### 固定比较区域，完整交付图片

`features/scan/layout.cpp` 中固定布局的 `stability_rect` 为 `[180, 0, 1440, 5760)`，使用客户区原生坐标。它排除最左侧主菜单的发光动画，保留分类图标栏、标题、全部物品与滚动条。着色器直接在这个矩形内读取纹理，不生成额外裁图，不缩放、模糊或使用差异容差。UNORM RGB 逐像素精确比较，Alpha 不参与最终 BGR 图片的业务语义。

`features/scan/usecase.cpp` 的 `stable_seconds` 是唯一的画面稳定时长定义，固定为 0.25 秒；不再区分导航和页面扫描计时。稳定跨度取自 WGC `SystemRelativeTime` 的 QPC 源时间（100ns），而不是 CPU 处理耗时。每次操作后的第一张有效新帧开始计时；画面不同时重置起点，至少有后续新帧跨过稳定时长才交付。输入边界通过同一时钟的 `capture::source_time()` 记录，排队旧帧不参与计时。

### 一个 WGC 缓冲，一张自有参考纹理

WGC 帧池仍为单缓冲。`FrameArrived` 只置位自动重置事件，通知允许合并，不把通知次数当作帧数。等待被唤醒后，扫描线程通过 `TryGetNextFrame` 尝试取一帧。

当前图片直接借用 WGC 纹理作为着色器输入，上一份比较参考存放在唯一的自有 GPU 纹理。首帧或比较域发生变化时才复制当前客户区到参考纹理；完全相同时不复制。各线程组先归并变化，再对一个 `uint` 结果做原子 OR；每轮 CPU 只读回这个小标记，不生成 CPU 差分图或逐帧 BGR 图片。

捕获启动时创建着色器、参考纹理、常量与结果缓冲、完成查询及最终图片 staging 纹理；要求 D3D11 Feature Level 11.0 和 WGC 纹理的直接 shader-resource 读取能力。不满足时明确报错并回滚，不切换到另一套 CPU 判稳流程。GPU 能力不在 `AppState` 构造或析构中初始化和回收。

`D3D11_QUERY_EVENT` 确认已提交的比较、复制和读回完成。等待期间检查停止、窗口和截止时间；停止与设备错误先记录原因，等已提交命令收尾后再归还 WGC 帧；到达截止时间只标记未完成，同样等收尾后把超时交回调用方。

### 消费者只分析稳定候选

`capture::wait_stable_frame(state, after_source_time, deadline, check, require_change)` 返回 `std::optional<Frame>`：值是被判稳的完整客户区画面，空值表示到截止时间仍未等到，由调用方按所处阶段给出失败文案。不返回旧 CPU 缓存。稳定后从当前 WGC 帧读回，而非旧参考纹理，确保比较域外的左侧菜单和帧时间也对应当前画面。

`check` 在扫描线程同步执行。没有帧时最多间隔 50ms 检查一次，但不因此读取帧池；UI 停止和 shutdown 设置标志并调用 `capture::wake(state)`，立即唤醒等待。一次操作共用截止时间，旧帧、通知和业务重试都不延长它。

导航拿稳定图片后定位图标、检查选中状态，不再计算菜单／标题差分。保持既有鼠标行为：初始化及点击后停放，滚轮后不新增归位；选中判断前仍按需停放。输入完成边界放在本次既有鼠标动作结束之后。

打开图鉴默认选中套装，不在采集范围内。扫描用例按导航静态分类表直接从发型开始，依次切换分类并采集。物品列表依赖游戏切换分类自动回顶，不发送物品列表向上滚轮。

页面扫描先取得稳定图片，再检测底部、定位接续锚点、读取问号与拥有状态并校验网格和重叠。首屏直接复用当前分类切换后的稳定帧，按首屏布局读取，不另行检测或等待回顶。翻页沿用上一张被接受的稳定页作为接续基准，不额外取一张 CPU 图片。未就绪候选被拒绝后，以 `require_change=true` 等待比较域实际变化并重新稳定，不在同一图片上重复解析，也不重发滚轮。方向和网格衔接等明确错误仍立即终止。

`Frame` 只携带源时间和完整客户区图片。输入完成后的源时间边界仍用于排除旧帧，不记录观察帧编号、CPU 读回时刻或逐页事务。

`Frame` 按值传递，其 `cv::Mat` 引用计数保留只读像素，不额外使用 `shared_ptr<Frame>`。原始 WGC 帧和 surface 不进入业务状态。异常诊断只使用已观察图片，不再等待新帧。

启动失败和正常、异常扫描收尾都在任务线程 COM 撤销前调用同一个 `capture::stop(state)`，分别停止会话、撤销通知、关闭帧池并释放 GPU 资源。回调只持有通知事件的独立句柄，不借用 `AppState`；[异步事件退订后的在途回调](https://learn.microsoft.com/en-us/windows/apps/develop/cpp-winrt/handle-events#revoke-a-registered-delegate)不会访问已释放状态或通知下一次会话。

## 结果发布与关闭

任务生命周期由 `scan::Phase` 表达；执行步骤由 `scan::Stage` 表达。
翻页达到上限直接返回 `error.scan.scroll_limit`；不再维护批次和分类的诊断会话状态字符串，也不用显示文案判断流程。

只有全部分类成功时，扫描才向终态放入完整分类数组；UI 只在成功终态更新 `state.result->last_success`。
新扫描失败或停止不会覆盖上次成功结果。中断分类数组直接丢弃，不导出半成品。
完整采集后发生捕获关闭或窗口恢复失败时，保留业务结果并携带警告；窗口恢复失败时继续保留恢复所需的窗口信息。
窗口恢复失败在成功、失败和停止终态中均通过 `Outcome::warning` 独立交付，优先提示用户手动恢复，不覆盖采集主错误。

主界面错误正文、通知条和明细警告仅翻译 `Error::message`，不递归展开内部阶段、原始详情与关联错误。
主动停止只显示“扫描已停止”标题，不重复显示停止原因；收尾警告仍通过通知条显示 30 秒，成功结果的警告也保留在分类明细中。

扫描返回前关闭 WGC 并尝试恢复游戏窗口；捕获关闭与窗口恢复失败均作为独立收尾警告，不覆盖采集错误。
任务线程在收尾之后、交付 UI 之前调用 `diagnostics::save`，正常成功和无收尾异常的主动停止直接返回，不创建诊断目录。
任务失败或有收尾警告时，仅生成 `data/diagnostics/<时间戳>/report.json`，以及有已观察图片时的 `failure.png`。
报告包含 manifest 中的程序版本、编译时间、发生时间、实际终态、当前进度、导航阶段、完整主错误与警告链、总耗时；不复制业务数组或维护分类历史。
图片从导航和当前分类的最近图片中按源时间选择，不额外捕获；PNG 保存失败仍尝试写报告，并在报告的 `image_error` 中保留原因。
目录、图片或报告写入失败只作为附加警告交付，不改变扫描终态或使完整结果失效。该报告也覆盖素材加载或任务线程 COM 初始化失败；任务启动前的失败直接由主面板提示。
保存诊断后调用 `release_run` 释放工作数据，最后撤销任务线程 COM 套间，保证 WIC 编码期间 COM 仍然有效。
不生成导航／分页日志、成功截图、会话检查点或分项性能统计。进程直接崩溃或被强制结束时可能没有报告。
用户关闭程序时，主窗口记录关闭意图并禁止新的业务操作；若正在扫描，先请求停止并继续处理消息。
收到终态并回收线程后，关闭流程通过 `PostQuitMessage` 退出消息循环；空闲关闭直接请求退出消息循环。
随后由应用 shutdown 等待尚未收尾的任务，撤销监听并销毁窗口。`WM_DESTROY` 只释放各窗口自己的资源，不再编排应用退出。
异常或消息循环失败时也按同样的 shutdown 顺序处理，确保模块状态和 UI 不先于任务释放。

## 手动验证重构

按项目约定，构建、测试和游戏操作由用户确认或手动执行。
重构后的重点路径为：正常完成并复制／保存；F8 与按钮停止；成功后再次扫描失败仍可复制旧结果；
扫描中关闭并等待恢复；连续扫描；切换主题与语言设置、从设置页打开项目仓库；初始化中途失败后的资源回收；捕获启动失败回滚与排队旧帧的输入边界过滤；无新帧时的停止、窗口检查和超时；左侧主菜单光效不阻塞判稳、分类栏和物品滚动会重新计时、未就绪静态页不重复解析；GPU 初始化失败回滚和原始帧访问收尾。

分类切换路径：从默认套装页面启动后，直接切换到发型并从首屏采集；后续分类沿图鉴顺序切换，不发送物品列表向上滚轮或等待顶部确认；画面判稳、卡片可读性、底部检测和翻页接续校验仍须正常工作。

错误展示路径：失焦时正文不追加“等待滚动响应”或分类选择阶段；主动停止正文留空；扫描失败并且窗口恢复失败时同时显示主错误与独立警告；成功后的收尾或终态诊断写入失败仍可复制结果；`report.json` 保留显示时省略的错误码、原始详情和阶段信息。

启动路径：普通启动同意或取消 UAC；从管理员终端启动；已有实例最小化后再次普通启动；从另一解压目录启动；扫描期间收到唤起消息直接显示主窗口；正常退出、初始化失败后均能重新启动。重复启动和取消授权不创建业务窗口或读写 `data/`。

诊断路径：正常成功和无收尾异常的主动停止不创建诊断目录；失败时仅有报告与可用的最后现场图；成功或停止但恢复失败时生成诊断；诊断目录不可写时不覆盖原错误、不废掉成功结果；连续扫描时不沿用上次诊断路径或现场图。
