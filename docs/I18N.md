# 维护中英文文本

编辑 `src/locales/zh-CN.json` 和 `src/locales/en-US.json`，两份文件使用相同的 key 和编号参数。
构建时自动生成内嵌文本表，也可单独执行：

```powershell
node scripts/generate-locales.js
```

## 显示文本

在 UI 边界调用 `core::i18n::wide`，取得供 DWrite、Win32 使用的 UTF-16 文本：

```cpp
#include "core/i18n/i18n.hpp"

auto label = core::i18n::wide(state, "action.start");
auto counts = core::i18n::wide(state, "summary.category_counts", owned, total);
```

文本中的 `{0}`、`{1}` 对应传入参数，可调整顺序。小数位、十六进制等格式先用 `std::format` 处理。

## 返回错误

```cpp
#include "core/message/message.hpp"

return std::unexpected(core::error("error.file.open_failed", path_utf8));
```

主界面正文、通知条和收尾警告只显示主消息：

```cpp
auto display = core::i18n::wide(state, failure.message);
```

主消息说明失败原因或用户需要处理的后果，不包含内部阶段、错误码、坐标和阈值。
同一段等待在不同阶段失败，对用户意味着不同的事，因此超时不用错误表达：底层等待返回空结果，由业务层按所处阶段给出原因与建议，采集层不产生面向用户的超时文案。
需要保留的参数仍可放在 `Message::args` 中，展示文案只引用用户需要的参数；中英文引用相同的编号参数。
系统或第三方的原始诊断通过 `core::with_detail` 保存；内部阶段、下层原因及附加失败追加到 `Error::related`。
完整错误格式化 `core::i18n::wide(state, error)` 仍用于详细错误弹窗，不直接拼进主界面。

扫描任务失败或有收尾警告时，`data/diagnostics/<时间戳>/report.json` 保存实际终态、阶段、分类、采集数量、主错误、收尾警告和全部原始参数、`detail`、`related`。
会影响用户操作的窗口恢复失败通过 `Outcome::warning` 独立交付，不依赖界面遍历错误链。

## 翻译参数

普通参数原样显示。参数本身需要翻译时，用 `core::text_key` 指定文本 key：

```cpp
auto failure = core::error("error.navigation.bounds_unknown",
                           core::text_key("group." + group_id));
auto display = core::i18n::wide(state, failure.message);
```

## 分类与分组键

分类 ID 和顺序只在 `features/navigation/navigation.cpp` 的静态分类表维护。
导航模块在编译期检查每个 `category.<id>` 和 `group.<id>` 是否存在于生成文本表；新增分类时同步补齐两份语言文件。
生成脚本校验中英文键与参数一致性及 C++ 字面量引用，不再读取外部分类表。
